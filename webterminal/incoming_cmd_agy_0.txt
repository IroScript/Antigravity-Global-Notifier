[নিয়ম: সর্বদা শুদ্ধ বাংলা লিপিতে উত্তর দিন; কোনো অবস্থাতেই বাংলিশ (Banglish) লিখবেন না। কোড ও কমান্ড ইংরেজিতে থাকবে।] না। আপনার বর্তমান ৫-স্তরের লক ব্যবস্থা যথেষ্ট নয়। বিশেষ করে একই Linux ব্যবহারকারী, একই `tmux` সার্ভার এবং একই ফাইল পারমিশন ব্যবহার করলে শুধু হুক দিয়ে সম্পূর্ণ বিচ্ছিন্নতা নিশ্চিত করা যায় না।

এক এজেন্ট যেন অন্য এজেন্টের কাজ দেখতে, পরিবর্তন করতে বা তার WhatsApp বার্তা গ্রহণ করতে না পারে, সেজন্য নিচের ১০টি নিরাপত্তা সেটিংস প্রয়োজন।

### এজেন্ট বিচ্ছিন্নতার ১০টি সেটিংস

| নং  | সেটিং                       | কী নিশ্চিত করবে                                                                       |
| --- | --------------------------- | ------------------------------------------------------------------------------------- |
| ১   | OS User Isolation           | প্রতিটি এজেন্টের আলাদা Linux ব্যবহারকারী ও ফাইল অনুমতি                                |
| ২   | Filesystem Isolation        | অন্য এজেন্টের ফাইল পড়া, লেখা বা মুছে ফেলা নিষিদ্ধ                                    |
| ৩   | Process Isolation           | অন্য এজেন্টের প্রসেস দেখা, বন্ধ করা বা নিয়ন্ত্রণ করা নিষিদ্ধ                         |
| ৪   | Tmux Isolation              | আলাদা tmux সার্ভার ও সকেট; অন্যের টার্মিনালে প্রবেশ নিষিদ্ধ                           |
| ৫   | WhatsApp Inbound Isolation  | গ্রুপ A-এর বার্তা শুধু এজেন্ট A পাবে                                                  |
| ৬   | WhatsApp Outbound Isolation | এজেন্ট A-এর উত্তর শুধু গ্রুপ A-তে যাবে                                                |
| ৭   | Memory & Session Isolation  | অন্য এজেন্টের কথোপকথন, ব্রেন, লগ ও সেশন পড়তে পারবে না                                |
| ৮   | Git & Credential Isolation  | অন্যের GitHub রিপোজিটরি, SSH key বা টোকেন ব্যবহার করতে পারবে না                       |
| ৯   | Tool & Network Isolation    | শেল, API, ডাটাবেস ও নেটওয়ার্ক দিয়ে অন্য এজেন্টে প্রবেশ নিষিদ্ধ                      |
| ১০  | Fail-Closed Verification    | নিরাপত্তা যাচাই ব্যর্থ হলে অ্যাক্সেস বন্ধ; প্রকৃত আক্রমণ-পরীক্ষায় প্রমাণ বাধ্যতামূলক |

### আপনার বর্তমান ব্যবস্থার সবচেয়ে বড় ৩টি দুর্বলতা

* শুধু CWD লক মানেই নিরাপত্তা নয়। এজেন্ট `cd`, absolute path বা অন্য টুল ব্যবহার করে বাইরে যেতে পারে, যদি OS অনুমতি দেয়।

* একই tmux সার্ভার ঝুঁকিপূর্ণ। সকেট অ্যাক্সেস থাকলে অন্য উইন্ডো নিয়ন্ত্রণের সুযোগ থাকতে পারে।

* Hook PASS মানেই সম্পূর্ণ নিরাপত্তা নয়। সরাসরি শেল, সাবপ্রসেস, সিমলিংক, API ও অন্যান্য বিকল্প পথও পরীক্ষা করতে হবে।

চূড়ান্ত নিয়ম: প্রতিটি এজেন্ট নিজের প্রজেক্টে পূর্ণ কাজের স্বাধীনতা পাবে, কিন্তু অন্য প্রজেক্টে কোনো অনুমতি পাবে না। কেন্দ্রীয় WhatsApp Bridge কেবল অনুমোদিত বার্তা আদান-প্রদান করবে। নিরাপত্তা কার্যকর করতে OS-স্তরের বিচ্ছিন্নতা ও প্রকৃত এন্ড-টু-এন্ড পরীক্ষা অপরিহার্য।
