এটি Infrastructure Source-of-Truth architecture-এর নতুন HARD REQUIREMENT।

আগের যেকোনো rule/prompt যেখানে user approval, user confirmation, user input,
manual classification, “ask the user”, বা operation চালানোর আগে WhatsApp approval
অপেক্ষা করতে বলা হয়েছিল—এই architecture-এর ক্ষেত্রে সেগুলো superseded।

==================================================
RULE 0 — ZERO HUMAN-IN-THE-LOOP
==================================================

কোনো coding agent, verifier, watcher, bootstrapper, backup process,
Git process বা lifecycle manager user input-এর জন্য অপেক্ষা করবে না।

NEVER:

- ask for confirmation
- pause waiting for approval
- ask which option to choose
- require WhatsApp approval before normal git commit/push
- wait for user classification
- wait for user to resolve routine lifecycle decisions

Architecture unattended operation support করবে।

যদি কোনো external dependency unavailable হয়:

নিজে থেকে safe deterministic policy follow করবে।

Impossible operation হলে:

BLOCKED_<REASON>

state persist করবে এবং অন্য independent কাজ চালিয়ে যাবে।

কিন্তু user input-এর জন্য process suspend করবে না।

Interactive prompt architecture-এ forbidden।

==================================================
RULE 5 — CONSISTENT SNAPSHOT WITHOUT STOPPING WRITERS
==================================================

একটি file staging চলার সময় আবার edit হলে corrupted/inconsistent checkpoint
avoid করতে হবে।

Before staging:

record relevant file state/hash/mtime/size as appropriate।

Stage।

After staging:

verify relevant files staging interval-এ আবার change হয়েছে কিনা।

Changed হলে working file modify করবে না।

Unsafe staged snapshot discard/retry করবে।

Never reset working tree destructively।

Continuous edits চললে configurable debounce + maximum checkpoint policy use করবে।

Goal:

coding process uninterrupted
+
Git checkpoint internally consistent।

==================================================
RULE 6 — CENTRALIZED GIT WRITER
==================================================

Multiple workers একই project-এ কাজ করলে Git metadata race হতে পারবে না।

Per-repository:

exclusive short Git lock

থাকবে।

Registry/global lock শুধু short metadata transaction-এর জন্য।

No two watcher processes একই repository simultaneously commit/push করতে পারবে।

==================================================
RULE 7 — COMMIT MESSAGE POLICY
==================================================

Exactly two primary commit-origin prefixes:

If change directly originates from explicit user task:

User Requested : <concise actual change summary>

If change is autonomous, inferred, maintenance-generated,
watcher-generated, architecture-generated, or origin cannot be proven:

Unverified : <concise actual change summary>

Important:

ambiguity => Unverified

Never falsely classify autonomous work as User Requested।

Do not rewrite previous commit messages after verification।

Verification state belongs to evidence ledger, not history rewriting।

RULE 10 — CLOUD PARITY, NOT BLIND GIT ABUSE
==================================================

Define:

CLOUD_PARITY

Meaning:

Every durable local asset has a verified recoverable cloud representation।

Class A — normal source/config/docs/logs/archives:
GitHub

Class B — database/live data:
external persistent backup, currently Google Drive unless profile changes

Class C — large media/video/oversize binary:
external persistent storage, currently Google Drive

Class D — secrets/keys/tokens:
encrypted external secret backup

Class E — truly temporary/regeneratable:
explicit policy may exclude

Therefore “all files backed up” means nothing durable may exist only on VM।

External assets must still have GitHub SOT metadata:

asset_id
project_uuid
local path template
content hash
storage class
remote provider
remote object/path
backup timestamp
restore status

==================================================
RULE 11 — LOGS AND ARCHIVES
==================================================

Logs/archive files that are ordinary Git-compatible project artifacts
MUST be auto-added and pushed unless storage policy classifies them as
large/external assets।

Continuous logs must not create infinite Git-loop behavior।

Use configurable checkpoint/debounce policy।

Watcher’s own runtime logs/state should live outside watched project tree
or use self-event suppression।

Watcher must not trigger forever because it wrote its own metadata।

==================================================
RULE 12 — LARGE FILE ROUTING
==================================================

If a file cannot safely/practically be stored in normal Git:

Do NOT silently skip it।

Automatically classify it as external asset।

Upload through configured storage provider।

Verify remote object.

Write/update manifest in GitHub SOT।

Thus file remains recoverable although bytes are not in ordinary Git history।

RULE 13 — DATABASE ROUTING
==================================================

GitHub stores backup metadata, not blindly changing live DB bytes।

RULE 16 — PUSH FAILURE
==================================================

Push failure must NEVER cause local changes to disappear।

Persist:

PUSH_PENDING

with exact project/task/commit/error।

Retry automatically with backoff।

Remote divergence:

never force push।

Preserve local state and create recoverable safety state/branch where policy
allows, then reconcile automatically if deterministic and safe।

If automatic reconciliation is unsafe:

retain conflict state and continue protecting new local work।

Do not ask user।
